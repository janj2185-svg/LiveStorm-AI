## What this package does

Lean Compose stand under `infrastructure/public-stand/`:

| Service | Role |
|---|---|
| Caddy | HTTPS (Let's Encrypt), SPA + API + WebSocket proxy |
| Flutter web | Built once into `web-dist` |
| API | FastAPI staging + `TEST_STAND_MODE` |
| Postgres | Durable data |
| Redis | Sessions rate-limits + one-time WS tickets |

Stand behaviour:

- Self-registration for every tester (no shared passwords as primary path)
- Auto email verify when SMTP is absent (`TEST_STAND_AUTO_VERIFY_EMAIL`) — UI/status is honest
- Signup sandbox wallet credit (not real money)
- Gifts monetization enabled for new testers so soft-ping can be received
- soft-ping catalog seeded on API boot from mounted artifacts
- Browser WebSocket via one-time tickets (`/gifts/events/ticket`, `/messages/events/ticket`)
- Sessions, logout, account delete
- Stand closes after `TEST_STAND_ENDS_AT`
- Real payments stay off

## Owner inputs (required before deploy)

1. VPS (Ubuntu 22.04+, Docker, open 80/443, ~4–8 GB RAM) **or** PaaS token
2. Domain DNS `A`/`AAAA` → VPS (or PaaS hostname)
3. `ACME_EMAIL` for Let's Encrypt
4. Optional SMTP (preferred). Without it: auto-verify + password-reset PARTIAL
5. Optional `OPENAI_API_KEY` for AI READY

Secrets (`JWT_SECRET`, DB/Redis passwords, Fernet key) are generated by
`generate-secrets.sh` on the server — never commit `.env`.

## Deploy

```bash
cd infrastructure/public-stand
./generate-secrets.sh
# edit STAND_DOMAIN + ACME_EMAIL in .env
./deploy.sh
./verify-external.sh https://YOUR_DOMAIN
```

Then open `https://YOUR_DOMAIN` on a second phone using **mobile data**.

## Tester instructions (once URL exists)

1. Open the HTTPS URL on phone or laptop (not localhost).
2. Create your own account.
3. If SMTP is off, registration auto-verifies (`registered_verified`).
4. You receive sandbox credits automatically — **not real money**.
5. Set a public handle in profile.
6. Try feed, messages, wallet, gift catalog, send **soft-ping** to another tester.
7. Delete your account when finished (Settings / `DELETE /v1/users/me`).
8. Report bugs via the stand bug URL. Include OS/browser and response request id.

## Known limitations

1. No public URL until owner hosting exists.
2. Password reset needs SMTP.
3. TikTok LIVE stays `BLOCKED_BY_PROVIDER_ACCESS`.
4. soft-ping is stand-seeded procedural asset path — not Hollywood AAA remaster.
5. Single API replica (in-process WS hubs).
6. AI assistant PARTIAL without OpenAI key.
7. MediaMTX/TURN full live plane is not in the lean stand compose.

## Security

- Never publish `.env`, JWT, DB, or Redis secrets.
- Stripe/real payments stay disabled unless separately approved.
- Fake TikTok events are tests-only and never prove LIVE.
